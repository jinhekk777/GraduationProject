# 技术架构

## 总体原则

可复用的系统行为使用 C++，内容配置和表现使用蓝图。项目初期仅保留一个运行时游戏模块；只有出现明确的依赖边界时，才拆分新的模块。

## 计划中的源码目录

```text
Source/GraduationProject/
  Core/          通用类型、接口和事件
  Interaction/   VR 交互接入与可抓取行为
  Assembly/      装配目标、验证、顺序和状态
  Teaching/      教学步骤与渐进式提示
  UI/            UI 数据和界面事件
  Analytics/     评分、体验记录和数据导出
  Debug/         调试信息与可视化
```

仅在开始实现相应功能时创建目录，不保留没有内容的架构空目录。

## C++ 职责

- 通用可抓取构件行为与交互接口。
- 装配目标组件，以及位置、角度和方向验证。
- 明确的构件状态机和装配状态机。
- 装配顺序及前置条件。
- 教学流程和提示等级判断。
- 评分、计时、体验记录、存取和数据导出。
- 向 UI 和视听反馈提供的数据定义及事件。
- 确有需要时提供编辑器校验或批处理工具。

## 蓝图职责

- 配置模型、碰撞、抓取姿态和装配目标位置。
- 配置不同榫卯的容差和内容数据。
- 绑定音效、震动、材质、Niagara 和动画。
- UMG 界面布局和动效。
- 具体榫卯实例及场景布置。

## 内容数据方向

优先采用数据驱动定义，避免为每种榫卯创建一个 C++ 子类。后续的榫卯定义应能描述构件、目标变换、装配前置条件、容差、教学步骤、知识内容和评分参数。

## 计划中的制榫加工边界

- 制榫加工与装配验证保持独立，不把工具加工逻辑塞入 `UAssemblyPartComponent`。
- C++ 负责加工步骤、工具类型、有效区域、动作方向、进度、错误、复位和完成事件。
- 蓝图负责工具外观、加工区域配置、模型阶段、废料掉落、木屑、音效和震动表现。
- 加工内容通过数据描述毛坯、步骤数组、目标区域、所需工具和完成后的模型状态。
- 第一版仅使用占位木块验证直榫的预设加工流程；通过 Quest 3 验证后再接入正式教学流程。
- 不实现自由雕刻、任意网格切割、体素破坏或运行时布尔运算。

仅在制榫原型正式开始实现时创建对应源码目录和类型。

## 直榫垂直切片资产契约

- 资产目录：`/Game/Mesh/zhi_sun`
- 榫头：`SM_zhi_sun_Tenon`
- 卯眼：`SM_zhi_sun_Mortise`
- 两个模型的位置、旋转和缩放完全相同时，即为正确完整装配状态。
- 榫头沿自身局部 Z 轴插入；具体正负方向作为可配置参数，不在 C++ 中硬编码。
- 第一版固定卯眼构件，只允许用户抓取榫头构件。
- 目标装配变换由场景中的目标组件或固定构件提供，不依赖资产名称推导。

## 验证层级

1. C++ 编译。
2. Unreal Editor 加载及资产配置检查。
3. 在适用功能上进行桌面 VR Preview 测试。
4. 使用 Quest 3 串流进行头显实测。

汇报时只能填写实际完成的验证层级。
